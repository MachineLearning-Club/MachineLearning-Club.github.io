Week 13 · Advanced

FiiCode II: Build a Working Application

Teacher Guide One 60-minute session; core + optional Research

Learning outcome

Explain the processing pipeline; trace one k-NN prediction; connect model output to a UI.

Teaching sequence

0–12 draw the pipeline; 12–27 trace distance and votes; 27–45 use the interactive app; 45–55 test invalid inputs; 55–60 identify a limitation.

Core: reproducible observations, one experiment and an explanation in ordinary language. Research (3p): additional mathematics, model investigation or application engineering. All features and labels in this project are synthetic; do not infer student traits or real room conditions.

Independent preparation project: these are deliberately simulated examples for practising data analysis and software engineering. They are not official FiiCode rules, datasets, judging criteria or submissions.

Optional mathematical investigations. Read the Course before beginning; these proofs and derivations are not required to complete the 60-minute core lesson. Use your browser’s print command for a printable version.

Contents

  • Proof B — nearest-neighbour order without square roots

Derivation A — why we scale features

The raw differences occupancy=20, wifi=2 and outlets=1 have unrelated units. A squared sum without scaling is dominated by features with large numeric ranges, not necessarily those carrying more information.

Fixed weighted squared distanced²(x,y) = Σ wᵢ ((xᵢ−yᵢ)/sᵢ)²

Our scales are (100,60,4,1,100), with weights (1,1,0.7,0.3,0.15). For two profiles differing only by 20 occupancy points, the contribution is (20/100)²=0.04; if they differ by one Wi-Fi level, the contribution is 0.7×(1/4)² = 0.04375.

Exercise: calculate the contribution of a 10-dB noise difference. Then determine whether removing the Wi-Fi weight changes the distance of two rows with identical Wi-Fi strength.

Proof B — nearest-neighbour order without square roots

For nonnegative numbers a and b, a < b if and only if √a < √b, because the square-root function is strictly increasing. Therefore ranking by nonnegative squared distance produces the same neighbour order as ranking by its square root.

Important distinction: squared Euclidean distance generally does not obey the triangle inequality, so it should not automatically be called a metric. Using it for ranking is still valid in this classifier.

Investigation C — ties and deterministic prediction

Suppose three nearest labels are avoid, good, consider: each has one vote. The model compares the total distance among neighbours of each label, then alphabetical label order if necessary. This makes two runs with identical data deterministic.

Exercise: construct a tie where changing distance weights alters the selected class. Explain why this is a meaningful model change that must be documented before evaluation.

References and reproducibility

All numeric claims can be reproduced with the same Python evaluation script and data. For Python input, output and basic mathematical notation, consult the club Python guide.
