FIICode II: Implementing the Application

Make the data pipeline, model and interface work together.

1. Start with a vertical slice

Real-life question. The model works in a notebook but nobody can interact with it.

Build the smallest complete path from input to useful output before adding features.

Worked example.

One CSV row → one prediction → a clear label on screen is a valid starting demo.

def predict(value):return 'high' if value>20 else 'normal'
print(predict(23))
Show the process step by step
  1. Choose one valid input
  2. Execute all stages
  3. Show one trustworthy output

Try this: change one input or value in the code, then predict the new output before running.

2. Separate responsibilities

Real-life question. Data cleaning and user-interface code are mixed together.

Keep input validation, prediction and display in small testable functions or classes. OOP can help but is not mandatory.

Worked example.

If the input is missing, return an understandable error instead of a stack trace.

def normalise(value):
    if value is None: return None
    return float(value)
print(normalise('12.5'))
Show the process step by step
  1. Validate
  2. Predict
  3. Format result

Try this: change one input or value in the code, then predict the new output before running.

3. Test ordinary and unusual cases

Real-life question. A demo crashes if someone enters a blank value.

Write tests for normal inputs, boundary values and missing data. Testing is cheaper than explaining a crash during a presentation.

Worked example.

Try values below, equal to, and above a decision threshold.

threshold=20
for n in (19,20,21): print(n,n>threshold)
Show the process step by step
  1. List test cases
  2. Run each case
  3. Fix a failure and rerun

Try this: change one input or value in the code, then predict the new output before running.
