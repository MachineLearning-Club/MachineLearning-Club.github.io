FiiCode II: Build a Working Application

Teacher Guide One 60-minute session; core + optional Research

Learning outcome

Explain the processing pipeline; trace one k-NN prediction; connect model output to a UI.

Teaching sequence

0–12 draw the pipeline; 12–27 trace distance and votes; 27–45 use the interactive app; 45–55 test invalid inputs; 55–60 identify a limitation.

13.1. Assemble the smallest end-to-end system

Week 12 supplied a problem, labelled rows and a working but weak baseline. Week 13 turns that into software with a visible input and a prediction the user can examine.

Data

Load the fixed 150 training examples

Five features plus one known label per row

Distance

Compare a new room with each training row

Scale features before computing weighted differences

Vote

Choose k nearest labelled examples

Majority vote, deterministic tie-break

Interface

Display the result and its nearest neighbours

A prediction is not a guarantee or calibrated probability

This is a legitimate supervised learning application. k-nearest neighbours (k-NN) does not need a separate numerical training loop: in this simple version it retains labelled examples and compares a new input to them.

13.2. Compute meaningful distances

We cannot directly subtract “noise in dB” from “Wi-Fi signal levels” and treat the result as a single comparable unit. Instead each feature difference is divided by a scale, squared and weighted:

Weighted squared distanced²(x,y) = Σ wᵢ((xᵢ−yᵢ)/sᵢ)²

Our fixed scales are (100, 60, 4, 1, 100) and weights are (1, 1, 0.7, 0.30, 0.15) in the order occupancy, noise, Wi-Fi, outlets, duration. They are documented educational design choices, not values learned from an external school dataset.

When k=3, three closest examples vote. Ties favour the class with the smaller sum of neighbour distances, then alphabetical class order. Distances and votes can be inspected in the working app below.

13.3. Try the real browser application

Predict the result before changing anything. Try a quiet, half-empty room and a noisy, crowded room. Change k from 3 to 1. The displayed neighbours and votes come from the published training CSV, not from a hardcoded decision tree.

13.4. Input validation is part of the algorithm

Software has to cope with incomplete or impossible observations: Wi-Fi strength 8 is invalid; a missing noise measurement cannot silently become 0 dB. Reject bad inputs with a visible explanation rather than secretly replacing them. Use only public, artificial examples in this practice application.

def valid_wifi(value):
    return isinstance(value, int) and not isinstance(value, bool) and 1 <= value <= 5
assert valid_wifi(4)
assert not valid_wifi(8)

The classifier itself belongs in a separate module, not hidden inside event-handler code. The browser runs an equivalent JS implementation; the downloadable Python project is the reference for tests and the final evaluation.

13.5. What makes the system usable?

Deliver a small application that accepts five inputs, identifies invalid data, predicts one of the three classes, and displays evidence. A visible result is more valuable than a vague claim that a machine-learning library was called.

Exit ticket: Trace the exact path from a changed Wi-Fi slider to a predicted label, then name one part that can be tested without running a browser.
