FIICode II: Implementing the Application

Teacher Guide Course overview and teaching sequence

Course summary

Make the data pipeline, model and interface work together. This lesson uses a practical classroom situation: A hackathon project predicts a category but has no usable application yet.

By the end: learners should be able to describe each topic using an input, an algorithmic step and an observable result, then run a small Python example and identify one limitation.

1. Start with a vertical slice

1.1. Real-life situation

The model works in a notebook but nobody can interact with it.

1.2. Understanding the concept

Build the smallest complete path from input to useful output before adding features.

1.3. Worked example

One CSV row → one prediction → a clear label on screen is a valid starting demo.

1.4. Try it in Python

def predict(value):return 'high' if value>20 else 'normal'
print(predict(23))
See the algorithm step by step

  2. Execute all stages
  3. Show one trustworthy output

2. Separate responsibilities

2.1. Real-life situation

Data cleaning and user-interface code are mixed together.

2.2. Understanding the concept

Keep input validation, prediction and display in small testable functions or classes. OOP can help but is not mandatory.

2.3. Worked example

If the input is missing, return an understandable error instead of a stack trace.

2.4. Try it in Python

def normalise(value):
    if value is None: return None
    return float(value)
print(normalise('12.5'))
See the algorithm step by step
  1. Validate
  2. Predict
  3. Format result

Try this: change one input or value in the code, then predict the new output before running.

3. Test ordinary and unusual cases

3.1. Real-life situation

A demo crashes if someone enters a blank value.

3.2. Understanding the concept

Write tests for normal inputs, boundary values and missing data. Testing is cheaper than explaining a crash during a presentation.

3.3. Worked example

Try values below, equal to, and above a decision threshold.

3.4. Try it in Python

threshold=20
for n in (19,20,21): print(n,n>threshold)
See the algorithm step by step
  1. List test cases
  2. Run each case
  3. Fix a failure and rerun

Try this: change one input or value in the code, then predict the new output before running.
