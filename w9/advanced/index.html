Week 09 · Advanced

Mid-Term Evaluation

Advanced Problem Sheet — evaluating a learned classifier

Five optional problems connect the earlier course's mathematical ideas to the practical mid-term. These exercises extend the 60-minute core without requiring new Python packages or university-level proofs.

Worked Example — errors are not distributed evenly

An imaginary ten-class classifier predicts 190 out of 200 digits correctly. Reporting 95% accuracy alone hides the pattern of mistakes. Suppose seven of the ten errors concern digit 1. If digit 1 has twenty held-out examples and only thirteen are correct, its recall is 13/20=65%, even though the overall model is 95% correct.

This is why a confusion matrix and class-specific counts can reveal problems that an overall metric does not.

Problem 1 — derive multiple scores from a confusion table

The following binary example was evaluated on 40 withheld cases:

Actual \ PredictedPositiveNegative
Positive128
Negative317

Find accuracy, recall for the positive class, and precision for positive predictions. Explain one scenario where recall matters more than overall accuracy.

Worked solution
  1. TP=12, FN=8, FP=3, TN=17.
  2. Accuracy: (12+17)/40=29/40=72.5%.
  3. Recall: 12/(12+8)=12/20=60%.
  4. Precision: 12/(12+3)=12/15=80%.
  5. In screening tasks where missed positives are important, low recall can be consequential even if total accuracy appears acceptable.

Problem 2 — identify data leakage in pseudocode

all_images = train_images + test_images
model.learn(all_images, train_labels + test_labels)
predictions = model.predict(test_images)
report_accuracy(predictions, test_labels)

Why does the third line no longer establish independent performance? Rewrite the order of operations so that test labels are not available during training or model selection.

Worked solution

The classifier learned from the test examples and their correct answers. This is data leakage. A valid assessment requires the testing images and labels to be separated before learning. A better pattern is: fit(train_X,train_y), then predict(test_X), then compare with test_y. Settings should ideally be chosen using a separate validation set, not the final test results.

Problem 3 — stratified sampling and class totals

Our classroom split includes 60 training examples and 20 held-out examples per digit for ten digits. Prove that it contains 600 training and 200 held-out examples, and that each row of a ten-class confusion matrix sums to 20.

Worked solution

There are ten labels, each contributing 60 training examples, so 10×60=600. Each label contributes 20 held-out examples, so 10×20=200. Each test image has exactly one actual label and one predicted label, so it adds one count to exactly one column in its actual-label row. Therefore the sum across that row is always 20, assuming every test image is evaluated once.

Problem 4 — compare two real models without exaggeration

On the provided fixed classroom test split, the reference program obtains 196/200 correct with k=3, and 195/200 with k=5. Compute the difference in number of mistakes and percentage points. Does this alone prove k=3 is universally better?

Worked solution

With k=3 there are 200−196=4 mistakes; with k=5 there are 200−195=5. k=3 has one fewer error on this set; accuracies are 98.0% versus 97.5%, a difference of 0.5 percentage points. One fixed split is not sufficient to claim universal superiority. For selecting k, use validation results and retain a separate untouched final test set.

Problem 5 — construct a fair evaluation protocol

A model builder tries six thresholds and three values of k, repeatedly picking the highest score on the same 200 held-out images. How many parameter combinations were compared? Explain why reporting the best test score as a completely independent final result is problematic. Outline a more defensible workflow.

Worked solution

There are 6×3=18 combinations. Even without directly training on the test labels, those labels influence the choice of the “best” model. That produces selection bias and can overfit the reported test subset. A better sequence is (1) make a separate train/validation/test split, (2) fit candidates on training images, (3) choose k and threshold using validation accuracy, (4) retrain if appropriate without accessing final test answers, and (5) evaluate once on final test images. Keep the random split and preprocessing settings documented so the result can be reproduced.
