Practical mid-term assessment — 20 points

Scenario: A school fair team must explain and demonstrate a working handwritten-digit recogniser. You will choose a suitable algorithm, trace one prediction using real digit data, run a second model configuration and write a short evidence-based conclusion.

Time: approximately 40 minutes of independent work after a 10-minute briefing, plus 10 minutes for saving and discussion. Allowed: the published course, starter notebook and your own calculations. Not required: neural-network training, Python package installation, GitHub or secret accounts.

Files: download the practical notebook (.ipynb), open it in JupyterLite, download the dataset CSV, and printable question sheet.

Important: This is a public practice assessment, not a secure confidential examination. The source images, answers and criteria are accessible on the website. A teacher administering an official marked test should prepare a controlled variant and collection method.

Part A — choose and justify an algorithm (5p)

For each of these three problems, choose a suitable first approach from the set fixed rule, supervised classification or unsupervised clustering:

  1. A school fan switches on whenever a measured temperature is above 26 °C.
  2. A computer sees 64 numerical pixels and must predict a digit from examples with known digit labels.
  3. A delivery service has point coordinates but no class labels and wants to group nearby locations.

Deliverable: three choices, each accompanied by one sentence explaining whether labels are available and what the output is. You may cite ID3, k-NN, k-means or a simple conditional as an example.

Part B — explain one real prediction (5p)

Investigate held-out example 17 in the interactive model below, with k=3 and the original grey-level values.

Investigate a real digit classifier

The pixels and labels come from a fixed, credited 800-image classroom subset of the UCI handwritten-digits dataset. Training uses 600 different images. You inspect 200 images withheld from that training. Nothing is submitted to a server.

Loading digit examples…

Click any pixel to increase its intensity by four, cycling through 0, 4, 8, 12 and 16. It changes only your inspected image, not the training/test sets.

Nearest labelled training images

These really are the nearest training images under the selected pixel-processing rule. Squared distances are shown; the classifier votes by label. A tie is resolved by total distance, then by the smaller label.

Evaluate all 200 untouched test images

Run the evaluation to count predictions for all 200 unmodified held-out images.

Inspect the confusion matrix and individual errors

Rows are the true digit, columns the predicted digit. A number off the diagonal is a mistake. Scroll the table sideways on narrow screens.

Explore these mistakes

  1. Copy its known label and calculated predicted label.
  2. Record the three nearest training labels, each with its displayed squared distance.
  3. Explain which digit wins the three-neighbour vote, and why the prediction can differ from the known label.

Deliverable: one short result table, the vote count, and a two-sentence interpretation.

Part C — run and compare two models (6p)

Open the provided Week 9 notebook. It contains the exact same training and test images as the web experiment. Use the default settings, then change one parameter.

  1. Run the default k=3 original-pixel model and record its correct count and percentage.
  2. Change K=3 to K=5. Keep the input data and preprocessing unchanged.
  3. Rerun evaluation, record the second correct count and explain which configuration has fewer errors on the same held-out set.
  4. Explain why this is an exploratory comparison rather than a final impartial competition score.

Deliverable: an executable notebook with two correct fractions and a short comparison. You can also include a screenshot of the web application's confusion matrix, but it does not replace executable notebook evidence.

Part D — make a defensible recommendation (4p)

A classmate claims: “We reached 98%, so this application reads every person's handwriting almost perfectly.” Write a short response that includes:

  1. One supported numerical observation with the exact held-out denominator.
  2. One specific observed failure, e.g. a misread digit, and a plausible interpretation.
  3. One limitation of testing on a small balanced dataset.
  4. One responsible next test or human-check recommendation.

Your answer should be understandable to a parent without requiring them to know how k-NN works.
