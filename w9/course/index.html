9.1. A real evaluation should produce something observable

Core idea

This week is a practical mid-term assessment. It checks whether you can choose an algorithm for a task, inspect the input data, reproduce a prediction, measure its success and communicate a limitation.

By this point you have encountered rule-based programming, decision trees, clustering, pixels, perceptrons and networks. It is less useful to memorise all their definitions than to answer one important question: which approach is suitable for the data and for the result we need?

The same real digit dataset from Week 8 remains available. You don't need to install a new package, register for an account or train a large neural network. The goal is to demonstrate a small, complete and honest learning workflow.

9.2. First select an appropriate type of system

Practical situationKnown informationSuitable first approach
Turn on a fan when temperature exceeds a fixed limitA rule and a measured temperatureOrdinary if, no model training required
Predict whether a school activity will take placeWeather data with past yes/no answersSupervised learning, e.g. a decision tree (Week 2)
Find natural groups of unlabelled delivery locationsCoordinates without class labelsK-means clustering (Week 3)
Read a handwritten number from an imagePixel arrays and known digit labelsSupervised image classifier: k-NN or a small neural model

Notice the difference between clustering and classification. A cluster number is only a group identifier until someone attaches a meaningful interpretation. A classification label is something that has a defined meaning in the training records.

Self-check — why not use a neural network for every problem?

A neural network needs appropriate data, training, validation and maintenance. For a deterministic threshold, a clear if statement is simpler and verifiable. For five unlabeled points, clustering may answer the relevant question. Selecting the smallest suitable tool is a valuable engineering decision.

9.3. Follow an evidence chain from question to conclusion

1 · Question

What digit is in this 8×8 image?

The desired output is a label 0 through 9.

2 · Data

600 training images, 200 withheld test images

64 values per image; original pixel counts are 0–16.

3 · Algorithm

Compare the image with labelled training images

k=3 means three nearest training images vote for the label.

4 · Evidence

Test predictions against answers not used in training

For default settings, 196 correct and 4 incorrect out of 200.

5 · Claim

Explain both what the result shows and what it cannot show

A strong claim includes dataset, metric, sample size and known limitations.

Think about what happens if a link is missing. A model that runs without an independent test has not demonstrated generalisation. A percentage without a denominator is ambiguous. A polished interface does not establish that the model is correct.

9.4. Practise the arithmetic before the assessment

Consider a fictional four-class evaluation with 20 held-out examples. If 16 are correct, accuracy is 16/20=80% and there are 4 errors. This does not guarantee that every class has an 80% success rate.

A class-specific example

Of five images whose true label is 2, a model predicts four as 2 and one as 7. For that class, recall is 4/5=80%. If a label is rare, simply reporting overall accuracy can conceal errors affecting it.

The same reasoning extends to our ten-digit confusion matrix. Its rows correspond to actual digits and columns to predicted digits. Every row in our balanced test set should sum to exactly 20.

Why is a test score not the same as a guarantee?

The model has been evaluated on a finite collection of examples from a particular distribution. A different writing tool, camera, person or background may produce different errors. A good evaluation statement includes that limitation explicitly.

9.5. Explore a real example before doing independent work

In Week 8 you inspected digit images and compared nearest training records. Here you can use the same model to prepare for the assessment. Change k while keeping the dataset fixed; inspect one mistake; run all 200 predictions to see the confusion matrix.

Investigate a real digit classifier

The pixels and labels come from a fixed, credited 800-image classroom subset of the UCI handwritten-digits dataset. Training uses 600 different images. You inspect 200 images withheld from that training. Nothing is submitted to a server.

Loading digit examples…

Click any pixel to increase its intensity by four, cycling through 0, 4, 8, 12 and 16. It changes only your inspected image, not the training/test sets.

Nearest labelled training images

These really are the nearest training images under the selected pixel-processing rule. Squared distances are shown; the classifier votes by label. A tie is resolved by total distance, then by the smaller label.

Evaluate all 200 untouched test images

Run the evaluation to count predictions for all 200 unmodified held-out images.

Inspect the confusion matrix and individual errors

Rows are the true digit, columns the predicted digit. A number off the diagonal is a mistake. Scroll the table sideways on narrow screens.

Explore these mistakes

Important: this activity exposes the correct test labels for learning. It is not a secret test and should not be presented as a formally blinded competition benchmark. For a serious project we would select settings with separate validation examples and evaluate once on a final unused set.

Teacher grading notes

A: award credit for choosing the correct family, naming input and output, and giving a meaningful reason. B: inspect the actual pixel-to-distance-to-label reasoning. C: require two executed configurations, correct test-set denominators and a reproducible notebook. D: reward one real mistake, its interpretation and a limitation stated without exaggeration. Do not require a particular programming library or memorised vocabulary.
