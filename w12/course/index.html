Week 12 · Course

FiiCode I: Read the Challenge and Establish a Baseline

Teacher Guide One 60-minute session; core + optional Research

Learning outcome

Define the prediction problem; audit 240 synthetic examples; establish a 15/45 baseline.

Teaching sequence

0–10 introduce the use case; 10–23 identify five features and labels; 23–39 inspect CSV; 39–51 measure the baseline; 51–60 discuss leakage.

Core: reproducible observations, one experiment and an explanation in ordinary language. Research (3p): additional mathematics, model investigation or application engineering. All features and labels in this project are synthetic; do not infer student traits or real room conditions.

12.1. Write a testable problem, not a slogan

Imagine a school showing different rooms for independent study. Should a student consider a room with most seats taken, loud background noise and weak Wi-Fi? The answer depends on the circumstances; we cannot pretend there is one universal opinion. For this exercise a simulation assigns each room profile one of three classes: avoid, consider, or good.

The contract

Input: five numerical descriptions of a hypothetical study space. Output: exactly one of three categorical labels. Success means predicting the supplied synthetic labels on data withheld from training.

FeatureAllowed valuesExample
Occupancy0–100%35%
Noise20–95 (illustrative dB)42
Wi-Fi1–5 signal levels4
Outlets0 or 11
Duration15–120 minutes60

The label is a judgement made for a fabricated classroom challenge, not a measured physical property. Predicting it is supervised classification because labelled examples are available. This differs from Week 3's unlabelled clustering and Week 11's deterministic sensor rules.

12.2. Inspect what is actually in the file

The complete source contains 240 unique simulated examples, generated with the documented random seed 20261117. Each label has 80 examples by construction. We separate them before choosing or evaluating a model:

PartitionRowsRole
Training150 (50/class)Examples available to the classifier
Validation45 (15/class)Compare candidate settings
Final test45 (15/class)One evaluation after settings are frozen

Student data are not collected. An ID such as SS024 identifies an artificial row, not a person. The CSV contains seven columns: ID, the five features, and the correct class label. A duplicate ID, missing feature or impossible value would indicate an input-quality problem. A duplicate example across partitions could also make evaluation misleading.

Because the dataset is intentionally balanced and constructed from three overlapping profiles, we cannot use the observed class frequencies to claim how often a real study space would be suitable.

12.3. A minimal working prediction

Before choosing a sophisticated model, construct a baseline. Here, the most frequent training class is chosen once and used for every prediction. There is a three-way tie: 50 avoid, 50 consider, 50 good. We resolve it alphabetically, so the constant predictor returns avoid.

Worked baseline evaluation

The separate validation set contains 15 actual avoid cases among 45 rows. A constant avoid prediction therefore scores 15/45 = 33.3%. We did not build a useful model, but we built a working, reproducible comparison point.

from collections import Counter
labels = ["avoid"] * 50 + ["consider"] * 50 + ["good"] * 50
most_common = sorted(set(labels), key=lambda c: (-labels.count(c), c))[0]
print(most_common)  # avoid — fixed tie-break

An improvement must beat the baseline on the same evaluation examples. It is not meaningful to compare scores from different test sets and call the change an algorithmic improvement.

12.4. Keep model selection and final checking separate

Training rows let the model learn or compare labelled examples. Validation rows help choose parameters. The final test rows are reserved until the choice is finished. If we repeatedly look at test scores and change parameters accordingly, the supposedly independent test becomes part of our design process.

Controlled experiment

Keep the 45 validation examples fixed. Compare one constant baseline with one candidate classifier. Record both a numerator and a denominator; avoid claims like “the AI is accurate” without an explicit sample.

Our data and scripts are public educational materials: a determined pupil can read the final CSV. Therefore this is a teaching hold-out, not a secure competition leaderboard. A real competition needs independent evaluation data and organiser-defined rules.

12.5. Your first deliverable

Start from the same Study Space Challenge project that continues through Weeks 13–15. Download the complete ZIP or run the Week 12 notebook. Explain the five features, three labels, how the split was made, and why the constant baseline gives 15 correct answers.

Exit ticket: What would count as one observation, what exactly are we predicting, and why is 33.3% not enough evidence of a useful application?
