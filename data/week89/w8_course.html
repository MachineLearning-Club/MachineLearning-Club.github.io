8.1. What does a classifier actually see?

Core idea

A handwritten digit looks like a picture to us. A computer receives a list of numerical pixel values. A classifier learns a relationship between those values and a known digit label.

Imagine a school using a digit reader to sort handwritten activity forms. A student writes “7”. Humans see the shape of a seven. Our software reads an 8-by-8 array of grey-level measurements. The darker a cell, the more ink is represented by its numerical value.

These images are not ordinary 8-bit grayscale photos: the original optical-recognition data were created by counting active pixels inside small blocks of larger handwritten images. Each of the 8 × 8 = 64 measurements is an integer from 0 to 16, not from 0 to 255. This makes a small dataset practical for an introductory lesson.

Read a 3×3 fragment

0415
01216
0213

0 means none of the original small block's pixels were active; 16 means all were active. The nine values are three rows of the larger 8×8 image, not a complete digit. The image's numerical features can be flattened into a list of 64 numbers in row order.

Connect this to Week 5

The same picture-to-numbers principle was used to explain RGB channels, grayscale intensities and thresholding in Computer Vision: Images as Data. The difference here is that we now attach a target label to the entire image and test actual predictions.

8.2. Separate what the model learns from what we use to test it

Core idea

Training data contain examples and their known answers. To evaluate a classifier, we keep a different collection of examples out of training and reveal those answers only when checking predictions.

Source

1,797 real digit images from scikit-learn's copy of UCI's optical digits

Ten labels, 0 to 9; each image contains 64 values.

Train

600 labelled images

60 of each digit. Our nearest-neighbour classifier remembers and compares these images.

Test

200 different images withheld from training

20 per digit. We predict each digit and then count which predictions match its known label.

We deliberately chose a balanced subset for the lesson. This is useful for comparing errors across ten classes, but it does not prove the model would perform equally well on every writer, camera, scan, classroom or real-world population.

Why must the test images not appear in training?

Predicting the same images already used for learning can be misleading. A system might simply remember examples instead of generalising. Holding images back offers a stronger, though still limited, test of how well the learned rule handles new inputs.

8.3. One prediction from start to finish

We can connect Week 4's preview of k-nearest neighbours (k-NN) to a concrete image classifier. Instead of training a neural network, we compare the new image to the already-labelled training images. The closest images vote for the class.

A miniature, three-feature example before 64 features

A fictional image is represented by only three numbers. It is Q = (2, 1, 3). Two labelled training examples are A = (2, 2, 3), label 4, and B = (5, 3, 3), label 7.

  1. Compare Q to A: squared distance = (2−2)²+(1−2)²+(3−3)² = 1.
  2. Compare Q to B: squared distance = (2−5)²+(1−3)²+(3−3)² = 13.
  3. One nearest neighbour: A is closer, so a 1-NN model predicts digit 4.
  4. Three nearest neighbours: find the three smallest distances among all training images and let the known labels vote.
Squared Euclidean distance for real 8×8 imagesd²(A,B) = (a₁−b₁)² + (a₂−b₂)² + … + (a₆₄−b₆₄)²

Using squared distance avoids calculating square roots and preserves the ordering of distances. For the real model, each distance compares all 64 measurements. If k = 3, the three closest labels vote; ties are resolved consistently using total distance and then the smaller digit label.

Is k-NN the same as a neural network?

No. It is a supervised learning algorithm with labelled examples, but k-NN compares directly against stored examples rather than learning a set of neuron weights. Weeks 6–7 showed different ways a model can learn and combine rules. The digit task is shared across these methods, not their internal mechanism.

8.4. Investigate the actual handwritten digits

Before opening the activity, predict what will happen when an image changes from grayscale to black-and-white. Does simplifying measurements always help recognition? The interactive example uses the real training and test images, not a drawn icon or a hardcoded prediction.

  1. Inspect Test example 1: record its known digit and the prediction with k=3.
  2. Click two pixels to change their brightness. Does the label predicted by your model change? Restore the image afterwards.
  3. Change the number of neighbours from 3 to 1. Which images are allowed to vote now?
  4. Select black-and-white threshold 8. Observe how preprocessing changes the measured distances.

Important: manually changing pixels produces an altered image. It is an experiment, not an additional independent test case. The whole-test accuracy button always evaluates the original unmodified held-out images.

8.5. Evaluation means counting successes and failures

For the unmodified dataset with the default settings (k=3, original 0–16 values), the classifier gives 196 correct answers out of 200 held-out examples:

Calculate accuracy

accuracy = correct / total = 196/200 = 0.98 = 98%. Therefore 200−196 = 4 images were misclassified.

Do not report “98% accurate at recognising any handwriting”. The supported statement is narrower: 98% accuracy on this particular balanced, 200-image held-out classroom subset with this particular distance rule.

A confusion matrix counts how often the model predicts one class when the real label is another. In a ten-digit task, its ten rows are the known digits and its ten columns are the predicted digits. Cells on the diagonal count correct predictions; other cells count errors.

Try Find next error in the experiment above. One example is held-out image 17: its label is 1, but our k=3 model predicts 8. Look at the image and its nearest training neighbours. Can you explain why a few labels could vote for 8 without concluding that either label was wrong?

What's the difference between accuracy and confidence?

Accuracy is an empirical fraction over a test set. The three-neighbour vote fraction is not automatically a calibrated probability. For example, three neighbours voting “8” does not prove an 8 has a 100% probability of being correct.

8.6. What can go wrong after a model looks impressive?

ObservationPossible reasonWhat to try
A thin digit becomes unrecognisable after a filterThresholding removed useful grey valuesCompare raw versus thresholded features on the same held-out images
A seven resembles a onePixel patterns overlap; nearest examples are ambiguousInspect errors and their nearest training images
Training performance looks perfect but test performance is worseThe system may remember training examplesEvaluate on images withheld before model choices
The app fails on phone-camera photosDifferent image size, brightness, alignment or backgroundCheck data compatibility and consider new real-world testing

Changing the model repeatedly after watching its held-out test scores can also bias an evaluation. In a larger project we would reserve a further untouched final test set, and use a validation set for choosing settings. In this classroom activity the test set is exposed for learning, so its scores should not be presented as a final competition-grade benchmark.

Optional: why a good score is not enough for high-stakes decisions

Even if a digit classifier misreads only four of 200 images, the consequences depend on what the numbers mean. A misread exercise number is inconvenient; an incorrectly recorded medical dosage or exam identifier could be serious. A human check is important when mistakes are consequential.

Revision and exit ticket

  1. Explain why a digit is represented by 64 numerical features.
  2. Identify the training and held-out sets and explain why they cannot overlap.
  3. Trace one k-NN vote from the distance comparison to the predicted label.
  4. Compute accuracy when 196 of 200 predictions are correct.
  5. Name one observed error and one action that might improve the model.
