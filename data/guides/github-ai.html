Create a real GitHub account and repository, build a small website with an AI coding agent in a browser-based development container, commit to main, then make the webpage public with GitHub Pages.

GitHub repository→Codespace + VS Code agent→Commit & push to main→Public website

What you need: a personal GitHub account, access to GitHub Codespaces and an internet browser. VS Code and Copilot can be used inside the Codespace; their availability and included usage depend on your account. You do not need to install Git, Docker or Python locally to begin.

End result: a public URL like https://USERNAME.github.io/my-first-ai-site/, containing a real interactive website created, checked and published by you.

01 / IDENTITY

Create your personal GitHub account

  1. Visit github.com/signup and follow GitHub's account creation instructions.
  2. Choose a username you can remember; it will be part of your site's URL.
  3. Verify your email and complete the security steps required by GitHub.
  4. Sign in. Do not share your password or recovery codes with the teacher, classmates or an AI assistant.

GitHub is intended for users aged 13 or above; local law can set a higher minimum. Students who cannot create accounts should complete this step with a school-approved alternative rather than sharing an account.

02 / PROJECT

Create one repository for your website

  1. On GitHub, click the + menu and choose New repository.
  2. Name the repository my-first-ai-site. This will produce a project-site URL under your username.
  3. Select Public. Turn on Add a README file so the repository has an initial commit and a main branch.
  4. Click Create repository.
Why not name it USERNAME.github.io?

You may do that if you want the account's main personal website at https://USERNAME.github.io/. For a first experiment, a project repository named my-first-ai-site is easier to distinguish from your future portfolio. Its published address is https://USERNAME.github.io/my-first-ai-site/.

03 / ENVIRONMENT

Create a Codespace — your cloud development container

Open the new repository. Select Code → Codespaces → Create codespace on main. A browser-based VS Code editor starts inside a cloud development environment. This is a real development container with files and a terminal—not merely a text editor.

What is inside a Codespace?

GitHub runs your working environment remotely inside a container on a cloud machine. Your editor connects to it. Editing happens in the Codespace; publishing happens later through GitHub Pages. Codespaces have free monthly usage limits for personal accounts. Stop the Codespace when finished; files committed and pushed to GitHub remain in the repository.

For beginners, use the default container. Creating a custom .devcontainer/devcontainer.json is not required.

04 / CREATE

Make the browser's entry file: index.html

  1. In the VS Code Explorer (left side), choose New File.
  2. Name it exactly index.html at the repository root, next to README.
  3. Insert the following tiny working example, or ask the AI agent in the next step to make one.
  4. Save using Ctrl+S.

Try this complete page if Copilot is not available:

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>My First Café</title>
<h1>My First Café</h1>
<p>Coffee costs 5 lei.</p>
<button id="add">Add coffee</button>
<p>Total: <output id="total">0</output> lei</p>
<script>
let total = 0;
document.getElementById("add").onclick = () => {
  total += 5;
  document.getElementById("total").textContent = total;
};
</script>
</html>

Or open a working example of the same café page to see what you are trying to create.

Predict: What will the total show after clicking Add coffee three times?
Show answer

15 lei. The JavaScript updates the total without a server or account.

05 / AI-ASSISTED DEVELOPMENT

Keep a VS Code agent beside your code

Open the Chat view on the right side. If Copilot is not available, install the GitHub Copilot extension in VS Code’s Extensions panel and sign in, then select an available Agent and use manual permissions for the first exercises. Availability and model choices can vary by account, VS Code version and environment.

Paste a focused prompt for the project:

Improve my single-file index.html website for a fictional café. Give it a clean, mobile-friendly design, two menu items with prices and working Add to cart buttons. Show the updated total. Use only HTML, CSS and vanilla JavaScript; no packages, passwords, APIs, real payments or external services. Explain what files you will change, then let me review your changes.
  1. Read the agent's plan and inspect the changes; do not click through everything automatically.
  2. Ask it to explain one new function in plain language.
  3. Run the website and click the buttons yourself.
  4. For an error, report what you observed, request a small correction and test again.

If Copilot is missing from your browser Codespace, use the official setup guide, or connect to your Codespace using desktop VS Code. GitHub Copilot Free has usage limits; the website project still works without an AI agent.

06 / TEST

See your running site before publishing it

  1. Open Terminal → New Terminal inside the Codespace.
  2. Run python3 -m http.server 8000. (This is a temporary preview server, not the final website.)
  3. Open the Ports tab and use the forwarded port 8000. If it does not appear, forward port 8000 manually.
  4. Choose Open in Browser, click each menu/cart button, then narrow the window to check mobile layout.

Test cases: 0 items → 0 lei; one coffee → 5 lei; three coffees → 15 lei. If your agent changed prices, calculate new expected totals before accepting the result.

07 / VERSION CONTROL

Commit and push to main

You are working directly on main for this introductory individual project. For larger team projects, branches and pull requests will be introduced later.

  1. Click Source Control on the left (branch icon). Review the list of changed files.
  2. Click a file to inspect its diff: what was added and removed. Confirm the agent did not add unrelated code or secrets.
  3. Click + to stage the intended changes.
  4. Write a meaningful message, e.g. Add interactive café menu.
  5. Click Commit, then Sync Changes or Push so the commit reaches the remote GitHub repository.
  6. Refresh the repository page on GitHub and confirm that index.html exists on main.
Terminal alternative: the same workflow
git status
git add index.html
git commit -m "Add interactive café menu"
git push origin main

Use this only after verifying the repository is on main. Git creates a local commit first; git push publishes it to your remote GitHub repository. A commit without a push will not update GitHub Pages.

08 / DEPLOYMENT

Publish your website with GitHub Pages

  1. Return to the repository on github.com.
  2. Open Settings → Pages from the repository's settings sidebar.
  3. Under Build and deployment set Source: Deploy from a branch.
  4. Choose branch main and folder /(root), then click Save.
  5. Once published, find Visit site on this page, or use the URL below.

Your Pages address: https://USERNAME.github.io/my-first-ai-site/

Important: this address is public. GitHub Pages can host static HTML, CSS and browser JavaScript but does not run your Python terminal server. The first deployment and subsequent pushes may take several minutes; GitHub documents that Pages publishing can take up to about 10 minutes.

09 / NEXT ITERATION

Build a repeatable engineering habit

Once your site is live, try adding one extra menu item with the VS Code agent. Then repeat the same sequence:

  1. Describe one small change.
  2. Review the proposed code changes.
  3. Preview locally and test the buttons.
  4. Commit the updated files and push to main.
  5. Refresh the published Pages URL after deployment finishes.
  6. Stop the Codespace when finished to conserve your usage allowance.
Why not leave the Codespace running?

Codespaces consume compute time and storage from your included quota. Stopping the environment saves compute usage. Your durable source code lives in the GitHub repository after you commit and push, not just inside a temporary session.
