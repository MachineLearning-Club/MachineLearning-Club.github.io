01 / NOTATION

One document, three things

A .ipynb file is a notebook document. It can contain descriptions, executable Python instructions and the results from previous runs.

Markdown cell

Temperature experiment

Predict the result before running the code.

Code cell
temperature = 18
print(temperature + 2)
Output
20

Python does not execute the text of a Markdown cell. A code cell executes in a kernel: a running Python environment that remembers previously assigned variables.

Why is a notebook useful for machine learning?

We can put one small dataset above a plot and a brief explanation below it. Instead of running a whole program from the start whenever we change one number, we can execute individual cells and inspect intermediate results.

02 / START

Open a notebook from the club

  1. Use the prepared notebook link or open JupyterLite from a week's Laboratory page.
  2. Wait until the interface loads. The first opening may take longer while the Python kernel downloads its components.
  3. The left file browser lists prepared notebooks. Click 01-nearest-prototype.ipynb to open it if it is not already displayed.

03 / YOUR FILES

Optional: upload a downloaded notebook

If you already downloaded a .ipynb file from a Laboratory page, it can be imported into the same interface:

  1. Open the club's JupyterLite editor.
  2. Click Upload Files (the upward-arrow button near the top of the left file browser), or drag the downloaded notebook into the file list.
  3. Choose your file. Its filename appears in the file browser; double-click to open it.

Do not upload passwords, student information, images of classmates or private data. JupyterLite files are normally stored only in your browser profile, not in a shared cloud drive.

04 / READ THE EXPERIMENT

Find the code cell beneath the explanation

The prepared notebook starts with a short explanation in a Markdown cell. Beneath it is Python code in a grey editor area.

  1. Click inside the code cell.
  2. Look for new = (3.4, 3.0) in this example. Those are coordinates of a new point we want to classify.
  3. Before changing anything, predict which of the two clusters the new point is closer to.

05 / EXECUTE

Run the selected cell

  1. Click the code cell and press Shift + Enter or the ▶ Run button in the notebook toolbar.
  2. The first Python run may take a little while while the browser-based kernel starts.
  3. Read the output that appears below the code. Some cells produce numbers; others display plots or images.
  4. For the original values, record the predicted class and explain what the visualised distances suggest.
Checkpoint: Does the cell show [1], [2] or something else beside it after running?
Explanation

The number shows the execution order within the current kernel session. A blank bracket means a cell has not yet completed an execution in that session.

06 / EXPERIMENT

Change exactly one input, then run again

In the notebook, find new = (3.4, 3.0). Replace it with new = (7.4, 7.0).

  1. Write your prediction before clicking Run.
  2. Run the code cell again with Shift+Enter.
  3. Compare the old and new predicted classes. What changed in the figure?
  4. Explain why moving the point changes the nearest learned centre.
Check the expected result

The original point is near the centre of class A. The modified point lies near class B, so the prediction should change from A to B.

This predict → run → observe → explain cycle is central to the club laboratories.

07 / KEEP YOUR WORK

Save a copy, then download it to your computer

Some club notebooks are published as prepared examples and can open read-only. If Save is disabled, use File → Save Notebook As… to create an editable copy inside JupyterLite.

  1. Use Save Notebook As… and choose a name like surname-week1-experiment.ipynb.
  2. Confirm that your changes appear in the copy. If necessary, rerun the edited cell.
  3. Choose File → Download to store a portable .ipynb file on your device.
  4. Open the downloaded file or check its filename. An in-browser Save alone is not a durable backup on another computer.
  5. Use the Laboratory's named-submission preparation controls, and follow the teacher's submission instructions. Those controls do not automatically send files to the teacher.
Important distinction: Save keeps an editable notebook in this browser's storage; Download creates a file you can back up, move to another device or submit.

08 / TROUBLESHOOTING

If something doesn't work

My cell says NameError

You may have run cells in the wrong order. Use Run → Run All Cells or restart the kernel and run from the top. A variable only exists after its defining code executes.

The Run button spins but no result appears

Check your connection and the kernel indicator. The first Pyodide kernel start may need to download resources. If it fails, reload the tab or try another current browser. Avoid repeatedly refreshing while a calculation is in progress.

I can read a notebook but can't save it

It may be a read-only published example. Use File → Save Notebook As…, then edit the copy. If the classroom administrator intentionally restricts storage, download the notebook and upload it to your own workspace instead.

My notebook disappeared when I opened another device

JupyterLite normally stores files in the original browser's local storage. They are not automatically synced across devices, private browsing windows or separate school computers. Download a .ipynb copy before leaving the session.

Can I use Google Colab instead?

Yes, as an optional alternative if the teacher permits it and you have a Google account. Google Colab runs notebooks through Google's service, while the club defaults to its own account-free JupyterLite.
