02 / RULES FIRST

Join only after understanding the rules

In the Overview, read the problem and score description. Check Rules for team size, submissions, datasets, external tools and any age or eligibility requirements. Sign in to your own Kaggle account and select Join Competition if eligible. Accept the competition rules before downloading restricted data or submitting.

Do all competitions have the same rules?

No. Some allow external datasets, some do not. Some allow collaborating as teams, some restrict team size or require particular submission notebooks. Submission limits and deadlines also vary. The Rules and Evaluation sections of the specific contest take precedence over this guide.

03 / UNDERSTAND THE DATA

What are train.csv, test.csv and sample_submission.csv?

A supervised-learning competition gives you labelled examples for learning patterns and separate examples to predict. In the Titanic beginner challenge, the training file includes whether passengers survived; the test file omits the answers.

train.csvFeatures + known answerLearn a rule or model
validationHeld-out labelled examplesCheck your model
test.csvFeatures, no answerPredict unseen labels
submission.csvID + your predicted answerDeliver the result

Why can't I evaluate accuracy on the hidden test file?

The correct test labels are not published to competitors. You can check how well your model generalises using a separate validation portion of training data. Kaggle calculates the final score on its hidden labels after you submit predictions.

05 / MODEL & VALIDATE

A small baseline before a sophisticated solution

A baseline is the first simple solution that runs from beginning to end. In the Titanic competition, a small decision tree can use only three numeric features. That is enough to practise the engineering cycle without complicated preprocessing.

On Kaggle, first join the Titanic competition and open a Python notebook with its data added. Then run the following example using the attached dataset path (the path may differ in other competitions).

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score

train = pd.read_csv("/kaggle/input/titanic/train.csv")
test = pd.read_csv("/kaggle/input/titanic/test.csv")
features = ["Pclass", "SibSp", "Parch"]

X_train, X_val, y_train, y_val = train_test_split(
    train[features], train["Survived"],
    test_size=0.2, random_state=42, stratify=train["Survived"]
)
model = DecisionTreeClassifier(max_depth=3, random_state=42)
model.fit(X_train, y_train)
print("Validation accuracy:", accuracy_score(y_val, model.predict(X_val)))

# Now train on all labelled rows before predicting the unseen test set.
model.fit(train[features], train["Survived"])
submission = pd.DataFrame({
    "PassengerId": test["PassengerId"],
    "Survived": model.predict(test[features])
})
submission.to_csv("/kaggle/working/submission.csv", index=False)
print("Saved", submission.shape[0], "predictions")

The sample trains a decision tree, but it is not claimed to be a winning model. It leaves out many potentially useful factors so students can focus on the mechanics. More advanced feature engineering belongs later.

Why do we split the labelled data into training and validation parts?

If we only measure performance on the examples used to train a model, we may confuse memorisation with generalisation. Validation checks predictions against known labels the model did not see while learning. Once the approach is chosen, it can be refitted on all available labelled rows for the final test prediction.

Does Kaggle allow me to use a prewritten notebook?

Many competitions provide shared notebooks and starter examples under Code. You may inspect and copy examples when permitted by their licenses and the competition rules. Understanding and testing your changes matters more than submitting unchanged code.

07 / SUBMIT
How Kaggle receives your work
Classic prediction competition: find Submit Predictions, upload your complete submission.csv and wait for Kaggle to validate the file and score it. This applies to the Titanic beginner competition.


Code competition: the contest may require saving and executing a notebook version (Save Version → Save & Run All) and submitting its output rather than uploading a standalone CSV through the same button. Follow the contest's own submission instructions, including any mandatory starter templates.


  1. Open the competition's Evaluation and Submission sections.
  2. Check the filename, number of predictions, expected headers and permitted format.
  3. Submit only if the competition is joined and you agree to the rules.
  4. Record the score and what changed since the previous attempt; use the competition's permitted submission limits.


A successful Kaggle notebook run is not necessarily a competition submission. Inspect the actual submission status on the competition page.


08 / EVALUATION
A leaderboard is feedback, not a lesson by itself


The Titanic metric is accuracy, the proportion of hidden cases predicted correctly. Other competitions may use a completely different metric. A useful experiment log records your validation score, submitted model, prediction file, public score and one justified next change.


Why might a higher public leaderboard score be misleading?
The public leaderboard often uses only a subset of hidden labels. Repeatedly adjusting a model to that subset can overfit it. The private evaluation uses different hidden examples. Focus on sound local validation and the official metric rather than random leaderboard attempts.


09 / CONTEST PREPARATION
What carries over to a possible FiiCode challenge?
Whether the competition happens on Kaggle or elsewhere, these are transferable skills:


  1. Understand the task's input, output and scoring rules.
  2. Explore the dataset before writing complex code.
  3. Train one reproducible baseline and validate it correctly.
  4. Produce the exact required output format.
  5. Keep versions of code, data choices and evaluation results.
  6. Interpret feedback without chasing noise or violating rules.
