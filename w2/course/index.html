2.1. A problem that can learn from examples

Core idea

Known examples → learn useful yes/no or category questions → predict an answer. ID3 is a method for constructing a decision tree from labelled data.

A school organises outdoor activities. The school diary records the sky, wind, temperature and whether students went outside. We want to predict a new day from previous examples, rather than writing every possible condition ourselves.

Classical rule

if sky == "rainy": stay_in

Written directly by a programmer.
Learned rule

Look at the recorded yes/no decisions and choose the most useful question.

Selected from labelled examples.
Prediction

Cloudy and calm? Follow the learned branches to reach yes or no.

The decision path is explainable.

The dataset is deliberately simplified and fictional. Do not treat this classifier as a real weather-safety decision system.

Check your understanding

Input/features: sky, wind, temperature. Output/label: go (yes or no). Learning: determining the tree questions from examples, not creating the weather data.

2.3. Which question should the tree ask first?

Imagine drawing one question at the root. Every possible value of that feature becomes a branch. A branch containing only one label is pure: it needs no further split.

INTERACTIVE EXPERIMENT

Choose the first question

Show the arithmetic for the selected split

The sky question is useful: sunny is all yes, rainy is all no, but cloudy remains mixed. By contrast, temperature produces two equally mixed groups.

2.4. Entropy — giving a number to uncertainty

Pure yes[4+,0−] → 0 bits
Mixed equally[2+,2−] → 1 bit
Mostly yes[4+,2−] → 0.918 bits

A set containing only yes or only no is easy to predict (entropy 0). A 50/50 mixture is maximally uncertain (entropy 1 bit for two possible labels).

Where do these numbers come from? (optional mathematics)

For a yes proportion p, use H(p) = −p log₂(p) − (1−p)log₂(1−p) with 0×log₂0 = 0. For p=0.5: H=−0.5×(−1)−0.5×(−1)=1. For p=1: H=0. You may use the computer to calculate the logarithms.

Fully worked — information gain of Sky

  1. Before asking: 6 yes / 6 no → H(before) = 1.
  2. Sunny occurs 4 times and is all yes → H(sunny) = 0.
  3. Cloudy occurs 4 times and is half yes/half no → H(cloudy) = 1.
  4. Rainy occurs 4 times and is all no → H(rainy) = 0.
  5. Weighted entropy H(after) = 4/12×0 + 4/12×1 + 4/12×0 = 1/3.
  6. Information gain IG(sky) = 1 − 1/3 = 2/3 ≈ 0.667 bits.

The other features have information gains of approximately 0.082 (wind) and 0 (temperature). Therefore, ID3 chooses Sky first.

Why use a weighted average of the branch entropies?

Different branches can contain different numbers of examples. A tiny pure group should not count as much as a large mixed group. Each branch is weighted by its fraction of the training dataset: H(after)= Σ (branch size ÷ total size) × H(branch).

2.5. Build the tree one decision at a time

Once a branch is pure, stop. If a branch is still mixed, repeat the procedure using the remaining features.

Step 1 / 4

The finished decision tree is a compact set of learned conditions:

IF sky = sunny:        predict YES
ELSE IF sky = rainy:   predict NO
ELSE IF sky = cloudy:
    IF wind = calm:    predict YES
    ELSE:              predict NO
Trace a new example

Sky is cloudy, wind is calm and temperature is cold. Follow the arrows. What is the output, and which feature did the algorithm not need?

Reveal the decision path

sky = cloudy → wind = calm → yes. Temperature was not needed, because it did not reduce uncertainty in these training records.

How would ID3 build a larger tree?
FUNCTION ID3(rows, remaining_features):
    IF all rows have the same label:
        RETURN that label
    IF no features remain:
        RETURN the majority label
    best = feature with maximum information gain
    FOR each possible value of best:
        subset = matching rows
        IF subset empty: use current majority label
        ELSE: build ID3(subset, other features)
    RETURN this decision node

Each recursive call sees a smaller subset or fewer available attributes. The algorithm eventually stops at a leaf.

2.6. Training versus testing

Correctly classifying the data that created the tree is not enough. Save some labelled examples for testing and ask the tree to predict them without looking at their labels.

SituationWhat you should report
A familiar weather combinationPrediction, real label and whether it matched
A never-seen sky value such as foggyA documented fallback and a warning
A tree that memorises training examples perfectlyAccuracy on held-out examples; training accuracy alone is insufficient

accuracy = number of correct test predictions / number of tested records. Because this diary is artificial, it does not establish real-world performance.

Optional research — must ID3 find the smallest possible tree?

No. ID3 uses a greedy choice at each node. Ciortuz, §4.1.1, solved problem 4, gives an example where the resulting tree is not the shallowest consistent tree.
