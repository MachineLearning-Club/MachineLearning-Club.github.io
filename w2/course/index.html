Decision trees and information gain

From a labelled table to a complete categorical ID3 tree, step by step.

Course summary

Decision trees make predictions by asking a sequence of questions. This lesson builds a categorical ID3 tree using eight training examples, rather than treating the algorithm as a black box. The key idea is information gain: at each node, choose the question that most reduces uncertainty about the target label. We then examine how a greedy algorithm constructs a tree and what perfect training accuracy does and does not establish.

Outcomes: interpret nodes, edges and leaves; calculate binary entropy and weighted conditional entropy; compare information gain; manually build a small ID3 tree; trace predictions and identify an incomplete-training counterexample.

Teaching note: 20 minutes can introduce the worked root split; students can study the full derivation separately. Prior mathematical material is optional—only fractions and logarithms are introduced as needed.

3.1. What a decision tree computes

A decision tree is a program whose internal nodes ask questions about an input, whose branches correspond to answers, and whose leaves produce decisions. For example: is the sky rainy? If yes, do not hold an outdoor demonstration. If no, another question might be needed.

In a hand-written rule system, the developer chooses the tree. In machine learning, a tree-building algorithm chooses questions from labelled training examples. The finished tree is still a simple program: the learning happened when the questions and leaves were selected.

def predict_example(sky, wind, temperature):
    if sky == "rainy":
        return "no"
    if wind == "calm":
        return "yes"
    if temperature == "warm":
        return "yes"
    return "no"

The program above will eventually be the result of our learning process; we have displayed it early to make clear what kind of object ID3 is trying to construct.

Teaching sequence: Experience AI, Lesson 4: Decision Trees — distinguish a rule-based tree from a tree learned from data.

3.3. Entropy and information gain

3.3.1. Measuring uncertainty

If all examples in a group have the same label, we are certain which label should be predicted for that group. If the labels are evenly split, uncertainty is greater. A common numerical measure is Shannon entropy.

H(Y) = − ∑ pᵢ log₂(pᵢ)

For two classes with proportions p and 1 − p, entropy is zero when either class has proportion one, and equals one bit at 50:50. We define 0 log₂ 0 = 0.

Worked calculation A — Entropy of the complete dataset.

The class frequencies are 3/8 and 5/8. Therefore:

H(Y) = −(3/8)log₂(3/8) − (5/8)log₂(5/8) ≈ 0.9544 bits.

The result is close to one bit because the dataset is relatively mixed.

3.3.2. Information gain of a question

To evaluate a candidate question, split the dataset into its possible answers, calculate the entropy of each subset, then average those entropies weighted by the number of examples. The decrease in entropy is the information gain.

Gain(Y, X) = H(Y) − ∑v (|Sv|/|S|) H(Y | X = v).
Worked calculation B — Should the root ask about sky?

The four sunny examples contain three yes and one no, so their entropy is approximately 0.8113. The four rainy examples are all no, so their entropy is zero.

H(Y | sky) = (4/8)(0.8113) + (4/8)(0) = 0.4056.
Gain(Y, sky) = 0.9544 − 0.4056 = 0.5488 bits.

Asking about sky reduces uncertainty by approximately 0.5488 bits.

3.3.3. Compare every candidate root

Wind divides the data into a calm group containing two yes and two no, and a windy group containing one yes and three no. Their weighted entropy is approximately 0.9056, so the gain is only 0.0488 bits. Temperature produces the same result.

3.4. Constructing the ID3 tree

3.4.1. The recursive idea

  1. If a node contains only one label, stop and create a leaf.
  2. Otherwise calculate the gain of each unused categorical feature.
  3. Choose the feature with the highest gain.
  4. Create one branch for each observed value of that feature, and repeat.
  5. If no features remain, use the majority label.

This is a greedy algorithm: it makes the best immediate split according to its local criterion, not an exhaustive search over all possible trees.

3.4.2. Continue the sunny branch

The rainy branch already contains only no answers. The sunny branch still contains three yes and one no, entropy 0.8113. Within this subset, splitting by wind gives a calm group containing two yes answers, and a windy group containing one yes and one no. The weighted entropy is 0.5, so the gain is 0.3113 bits.

Temperature gives the same gain. With the fixed feature order (sky, wind, temperature), we choose wind in a tie. The calm branch becomes a yes leaf. For sunny and windy cases, temperature distinguishes warm → yes from cold → no.

3.5. Generalisation, stopping and other tree algorithms

3.5.1. Perfect training fit is not a guarantee

The tree classifies every row in Table 3.1 correctly. But imagine we had not observed the sunny/windy/cold case. A different tree might still fit all the remaining examples while giving an incorrect answer for that unseen combination. This is not a bug in Python; it is a limitation of what the supplied data can establish.

3.5.2. ID3 is not the same thing as CART

Classical ID3 chooses categorical tests using information gain and can create a branch for each category. The interactive tree demonstration used in the lab visualises CART, which commonly makes binary splits and can handle numerical thresholds. The shared intuition—reducing disorder—is valuable, but we should not claim the two implementations are identical.

3.5.3. How to avoid misleading conclusions

Large trees may fit noise, and the best greedy split is not necessarily part of the smallest possible global tree. In Week 4 we will introduce evaluation on held-out examples, error tables and the distinction between fitting and generalising.
