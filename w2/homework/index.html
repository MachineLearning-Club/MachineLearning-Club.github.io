Week 02 · Homework

Supervised Learning: ID3

Real-life situation — planning the school sports afternoon

The school's organisers have recorded the sky, wind, temperature and whether previous outdoor games went ahead. The committee needs a transparent prediction assistant: it should explain which questions led to a yes/no prediction and identify when it does not know the answer.

You will use club-events.csv (12 labelled examples). This exercise concerns a simplified diary; a real school should still follow weather warnings and its safety policy.

Mandatory (1p) — Read the data and find a rule

  1. Open the prepared ID3 notebook. First run it unchanged. The data are already loaded.
  2. Identify the three input features and the target label. Count all yes and no results.
  3. Use the browser information-gain experiment to compare Sky, Wind and Temperature.
  4. Show why IG(sky) ≈ 0.667 bits using the group counts and formula below. Name the best root question.
  5. Draw a simple decision tree that classifies the twelve rows and trace one prediction for cloudy / calm / cold.
Formula guide

Entropy of a group of yes/no outcomes:

H = −p_yes log₂(p_yes) − p_no log₂(p_no).

Information gain of a question:

IG(feature) = H(all) − Σ (number in branch / total rows) × H(branch).

For Sky use H(all)=1, H(sunny)=0, H(cloudy)=1, H(rainy)=0, each with 4 of 12 examples. Therefore IG(sky)=1−(4/12×0+4/12×1+4/12×0).

Check the first classification

Sky=cloudy → Wind=calm → Go=yes. Temperature is unused in this tree, even though it is present in the original table.

Homework (2p) — Make the classifier useful

Imagine the school collects more diary entries and encounters weather conditions that were missing from the old data.

  1. Reserve test cases. In club-events.csv, set aside rows 4, 7 and 11 (counting the first data row as 1). Do not train on those three; only the other nine may determine the learned tree.
  2. Retrain. Print the information gain of each root candidate using only the nine training rows. Explain whether the chosen root differs from the full-data tree.
  3. Explain one prediction. Add a function that returns the whole decision path, for example sky = cloudy → wind = calm → yes. Display a complete path for each of your three test records.
  4. Handle unknown input. Ask for sky=foggy. If the tree has no branch for this category, return the training majority label and print Warning: unseen feature value. If there is a tie, use the alphabetically first label and state that rule.
  5. Test fairly. Count correct predictions on the three withheld records and compute accuracy = correct / 3. Include a small table with actual label, predicted label and correct/incorrect.
  6. Reflect. Explain in no more than four sentences why a model trained from a tiny fictional dataset should not be used as a real safety policy.
Algorithmic steps
  1. Separate the rows into training and testing.
  2. For each feature, group the training rows by feature value.
  3. For each group, calculate entropy and take a size-weighted average.
  4. Choose the feature with the greatest information gain and recurse on mixed groups.
  5. Traverse the learned tree for each test input; never use its test label during prediction.
Need a starting point?

The prepared notebook already contains a categorical ID3 function. Modify its input rows and the function that traverses the tree; do not replace the algorithm with a library classifier. You can use simple lists, dictionaries and counting.

Research (3p) (optional)

Design an example where ID3 chooses a locally promising root but a different tree has fewer decision nodes or levels. The optional Advanced exercises investigate greedy decisions, unnecessary features and contradictory examples.
