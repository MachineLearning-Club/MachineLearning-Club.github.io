What Is AI? Rules and Learning

How can a computer make a decision, and what changes when it learns from examples instead of following a fixed rule?

Essential question

A programmer can specify a rule directly. A learning algorithm instead calculates a model from observed data. In this lesson, you will follow both approaches from input to output.

Teacher Guide Course overview and teaching sequence

Course summary

A computer can perform intelligent-looking tasks by following rules written by a programmer, or by learning patterns from examples. This course explains the difference, introduces features and labels, and shows how a model turns training data into a prediction. The emphasis is not on the complexity of modern AI, but on understanding what an algorithm does and what its output can reasonably mean.

By the end: distinguish rules from learned predictions; identify input features, training labels and output; explain training versus testing; recognise why a confident or correct-looking prediction may still be wrong.

1.1. Programs, rules and AI

Core idea

A fixed-rule program follows conditions written in advance. Machine learning estimates a decision-making model from examples; both can be parts of AI systems.

Consider a program that switches on a light when the measured brightness falls below a fixed threshold. It may be useful, but the rule is explicitly supplied by its programmer. Nothing in the example requires the machine to learn from earlier observations.

def turn_on_light(brightness):
    return brightness < 300

Rule-based system: a system whose decisions follow a set of conditions or procedures explicitly defined in advance. Machine learning: a family of methods that estimate useful patterns or parameters from data rather than requiring a separate programmer-written rule for every situation.

Artificial intelligence is a broader field. It also includes search, planning, reasoning, language technologies and approaches that may or may not involve learning. Consequently, not every automated system uses ML, and not every AI system is a neural network.

Programmed rule

Switch a lamp on when brightness is below 300.

The condition is written by a programmer.
Learned model

Estimate a person's preferred light level from labelled observations.

The model's parameters come from data.
Search and planning

Find a path through a maze using a search algorithm.

Search can be AI without using machine learning.
Check your understanding

A light switches on when brightness falls below 300. Is that necessarily machine learning? What would need to change?

Reveal the reasoning

No. The programmer supplied the condition. A learning-based version could calculate a threshold or predictive function from labelled observations.

1.2. Learning from examples

Core idea

A training example contains input features; supervised examples also contain a known answer (the label). The learned model uses these to predict answers for new inputs.

A model is trained using examples. Each example contains information about the object or situation. In supervised learning, the examples also contain an answer, called the target or label. In classification, the model predicts a category; in regression, it predicts a numerical value.

1.2.1. Features and labels

Suppose a fictional sensor sorts two kinds of classroom demonstration objects. It measures two properties: size and reflectance, both on arbitrary numerical scales. A teacher labels each example as class A or B.

Here, size and reflectance are the features. The values A/B are training labels. The machine does not automatically understand the names: it only uses the information represented in the table.

1.2.2. Three families of learning

Supervised learning: examples have target answers, such as A/B. Unsupervised learning: data have no supplied target categories, and the algorithm may instead discover groups. Reinforcement learning: an agent explores actions and learns from rewards or other feedback. These approaches solve different kinds of problems; they are not competing names for the same method.

Check your understanding

In Table 1.1, which values are features, and which are labels? Why are labels useful?

Reveal the reasoning

Size and reflectance are input features. A and B are labels: they tell a supervised learning algorithm which category each example belongs to.

1.3. Training, prediction and testing

Core idea

Training constructs the model, inference uses it, and testing checks predictions against independent known answers. These are three different operations.

We should keep three processes conceptually separate:

  1. Training: compute a model from labelled examples.
  2. Inference: give the model a new input and obtain a predicted category.
  3. Testing: compare predictions with independent, known answers that were not used to fit the model.
Training

Labelled examples → Learning algorithm → Trained model

The training data determine the model parameters. New examples may change them.

Inference

New input + Trained model → Prediction

The trained model is used without changing its parameters.

Testing

Prediction + Known test label → Correct / incorrect

A held-out example gives evidence about performance on unseen cases.

If we test only on the training examples, the accuracy may look perfect even when the algorithm has memorised misleading details. A model may also learn from a biased selection of examples. For a classroom experiment, a separate test set and a short log of mistakes are more useful than a single impressive prediction.

Check your understanding

A classifier correctly predicts all six training samples. Does that prove it will work on a seventh, unfamiliar sample?

Reveal the reasoning

No. Training-set accuracy does not show generalisation. Use separate labelled test examples that were not used to train the model.

1.4. A complete small numerical model

Core idea

Learn a representative point (prototype) for each class from the training examples. Predict a new point's class by finding the nearest learned prototype.

We will not attempt to reproduce the image model behind Quick, Draw! in the first session. Instead, we can train a tiny transparent classifier that makes the idea of a learned parameter visible.

1.4.1. Learn class prototypes

For each class, calculate the average of its feature values. The average pair becomes the class prototype. From Table 1.1, the two prototypes are approximately A = (2.33, 2.33) and B = (7.33, 7.33).

1.4.2. Predict from the nearest prototype

For an unseen input (2.5, 2.2), compare its straight-line distance to A and B. It is much closer to A, so the model predicts A. The Python function below performs the same operation; its class prototypes were calculated from training examples.

Complete example: the prototypes are calculated from training data, not entered manually.

from math import dist

training = [
    ((2.0, 2.0), "A"), ((2.0, 3.0), "A"), ((3.0, 2.0), "A"),
    ((7.0, 7.0), "B"), ((7.0, 8.0), "B"), ((8.0, 7.0), "B"),
]

# TRAIN: calculate a representative point for each class.
def learn_prototype(label):
    group = [point for point, answer in training if answer == label]
    return (
        sum(point[0] for point in group) / len(group),
        sum(point[1] for point in group) / len(group),
    )

model = {label: learn_prototype(label) for label in ("A", "B")}

# PREDICT: use the trained model on an unseen point.
def predict(point):
    return min(model, key=lambda label: dist(point, model[label]))

print(model)  # A and B prototypes learned from the six rows
print(predict((2.5, 2.2)))  # A

Check your understanding

Move training example A1 closer to class B. What changes before retraining? What changes after retraining?

Reveal the reasoning

Before retraining, the dot moves but the learned class A prototype does not. After retraining, the prototype shifts toward the edited point and some predictions can change.

1.5. Mistakes, confidence and responsibility

Core idea

A prediction is an algorithmic output, not a guarantee. Good evaluation asks when and why a model fails, not only when it succeeds.

A model may predict a class even when it has never seen a similar input. For example, the nearest-prototype program still returns A or B for a sample far outside the observed range. That is not evidence the result is dependable.

A classification system may display a confidence score. In many systems this is a model-dependent score, not a guarantee of correctness. We should not confuse an output with an explanation, and we should not trust a demonstration simply because it succeeds on the teacher's first example.

  1. Were the training examples varied enough?
  2. What is different about the failed examples?
  3. Was the test example genuinely unseen?
  4. Does the system process personal data, faces or voices?

For the school lab, use ordinary objects and synthetic data. Do not upload images of classmates or any personally identifying information.

Check your understanding

The model assigns class A to a point far outside the training data. Why should you be cautious?

Reveal the reasoning

Nearest-prototype classification always returns the closest class, even for unfamiliar inputs. A class label alone does not establish that the model has seen relevant examples or is reliable.
