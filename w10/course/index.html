Week 10 · Course

Generative AI: GPT, Data and Society

Teacher Guide Course overview and teaching sequence

Course summary

Tokens, next-word prediction, social-media data, ethics and responsible use. This lesson uses a practical classroom situation: A social-media platform recommends posts and a language model writes a summary of them.

By the end: learners should be able to describe each topic using an input, an algorithmic step and an observable result, then run a small Python example and identify one limitation.

1. How language models predict text

1.1. Real-life situation

A phone suggests the next word while you type.

1.2. Understanding the concept

A language model learns statistical patterns of tokens; tokens may be words, parts of words or punctuation.

1.3. Worked example

Given 'The weather is', a model may assign different scores to 'sunny', 'cold' and 'changing'.

1.4. Try it in Python

sentence = 'The weather is'
print(sentence.split())
See the algorithm step by step
  1. Split a sentence into tokens
  2. Inspect possible continuations
  3. Choose one token

Try this: change one input or value in the code, then predict the new output before running.

2. Where training data come from

2.1. Real-life situation

A recommendation platform records which posts people click.

2.2. Understanding the concept

Large-scale data may contain preferences, biases, copyrighted materials and personal information. Having data does not always give permission to reuse it.

2.3. Worked example

Two users who click on different posts can receive very different recommended content.

2.4. Try it in Python

clicks = {'sports':4,'music':2}
print(max(clicks,key=clicks.get))
See the algorithm step by step
  1. Identify data being recorded
  2. Ask who benefits
  3. Discuss consent and representation

3. Behaviour and recommendation systems

3.1. Real-life situation

Someone watches three football videos, so the platform offers a fourth.

3.2. Understanding the concept

Recommenders may rank content based on observed behaviour; recommendation is not the same as knowing a person's intentions or values.

3.3. Worked example

A click is a noisy signal: curiosity and disagreement can both cause clicks.

3.4. Try it in Python

print('Clicks ≠ complete understanding of a person')
See the algorithm step by step
  1. Observe the suggested content
  2. List alternative explanations
  3. Question a recommendation loop

4. Reliability, ethics and control

4.1. Real-life situation

A generated answer invents a source it cannot actually provide.

4.2. Understanding the concept

Language-model output must be checked against evidence. Discuss hallucination, privacy, misinformation, environmental costs, labour and social impacts.

4.3. Worked example

A confident-sounding claim without a verifiable source is still uncertain.

4.4. Try it in Python

claims = {'claim one':'supported','claim two':'uncertain'}
print(claims)
See the algorithm step by step
  1. Find a claim
  2. Look for independent evidence
  3. Mark it supported/uncertain/unsupported
