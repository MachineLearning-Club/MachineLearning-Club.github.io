10.1. A sentence becomes a sequence of smaller units

Core idea

Computers process language as sequences of tokens—which may represent whole words, word parts, punctuation or special units.

A phone can offer text suggestions because a language model has learned patterns in sequences. Our exercise below uses a simplified, educational splitter; real GPT-style tokenisers can use entirely different subword units.

Worked example

AI can help students! → ["AI","can","help","students","!"] in our toy representation. We do not claim these are the token IDs used by a real model.

Why is splitting on spaces not a real tokenizer?

Different tokenisers use different vocabularies and encoding rules, often breaking uncommon words into pieces. The point here is the sequence, not the exact token IDs.

10.2. A model chooses between possible continuations

Imagine the unfinished phrase Today the sky looks .... Choose one of three possible next words.

Today the sky looks …

Choose one word.

Illustrative numbers, not from a live modelP(blue)=0.60, P(cloudy)=0.30, P(unusual)=0.10

High likelihood means that a candidate is plausible in the context, not that the completed sentence has been independently verified as true. Real language models predict tokens using more complex mechanisms than this classroom toy.

10.3. Why two people might see different feeds

This toy recommender ranks two subjects by recent click counts. It illustrates behaviour-based ranking, not an actual social network algorithm.

  1. Predict which topic comes first at 5 science clicks and 2 music clicks.
  2. Set music to 8 clicks and explain what changed.
  3. Give two different reasons why someone might click a post.

A click can reflect interest, surprise or disagreement. It is evidence of an interaction, not a complete description of a person. Personalisation can also make a feed increasingly repetitive.

10.4. Separate a claim from its evidence

Core idea

Claim → source → check → verdict. Fluent text cannot replace evidence.

A fact-checking calculation

A draft newsletter claims: “80% of pupils voted yes.” The original anonymous count is 12 yes and 8 no. Calculate 12/(12+8)=12/20=0.60=60%. The draft is incorrect even if the sentence sounds confident.

QuestionWhat students should record
What exactly is claimed?“80% voted yes.”
What is the independent source?The original anonymous tally: 12 yes, 8 no
Does the calculation support the claim?No. It supports 60%
What should happen?Correct the number before publication
How does Week 11 connect?

Software can calculate 12/20 with ordinary Python code and tests. An AI assistant may help draft the surrounding paragraph, but the numerical result should come from verifiable data and a deterministic calculation.

10.5. People still control data and actions

Before

Do not share passwords, pupils’ faces, personal messages or confidential files.

During

Ask for sources and check important claims.

After

Review the final draft before publishing, sending or changing files.

An assistant that suggests a sentence is not the same as an application authorised to post it. In an agent-like application, software controls which actions are allowed and when a human approves them.

Optional, for curious students: a tool-using agent

A chatbot returns text. A program with tools can ask another function to calculate or fetch data, then inspect the result. The function should do the actual calculation; the human remains responsible for permission to publish. This is a simplified interpretation of Gavriluț's Course 2 and Lab 3, not an exercise in building an agent harness.

Checkpoint

  1. Give an example of a token that is not a full word.
  2. Explain why the most likely continuation need not be true.
  3. Describe one limitation of interpreting clicks.
  4. Correct the newsletter's 80% claim using the given counts.
  5. State one action that should require a human check.
