FIICode IV: Hackathon

Teacher Guide Course overview and teaching sequence

Course summary

A real challenge, a functioning application and an evidence-based presentation. This lesson uses a practical classroom situation: Your team must present a working solution, not just a model trained once.

By the end: learners should be able to describe each topic using an input, an algorithmic step and an observable result, then run a small Python example and identify one limitation.

1. Plan the final sprint

1.1. Real-life situation

A working project still has unfinished features.

1.2. Understanding the concept

Choose the tasks that make the demo reliable and understandable. Avoid major untested rewrites near presentation.

1.3. Worked example

Prioritise 'runs on a fresh browser' before 'add five new model types'.

1.4. Try it in Python

tasks=['test inputs','README','demo script']
print(tasks)
See the algorithm step by step
  1. List critical tasks
  2. Assign responsibility
  3. Verify finished work

Try this: change one input or value in the code, then predict the new output before running.

2. Present a result with evidence

2.1. Real-life situation

A judge asks what improved and how the team knows.

2.2. Understanding the concept

Show the problem, baseline, method, validation metric, a real example and one limitation. A demonstration is an argument supported by observable outputs.

2.3. Worked example

'Accuracy improved from 70% to 78% on the same 50 held-out examples' is stronger than 'our AI is very accurate'.

2.4. Try it in Python

print('Problem → solution → evidence → limitation')
See the algorithm step by step
  1. Demonstrate input and output
  2. Show a comparable metric
  3. Name one failure mode

Try this: change one input or value in the code, then predict the new output before running.

Bibliography: IOAI 2026 Syllabus.

3. Deliver something someone else can run

3.1. Real-life situation

The team members want to reuse the project later.

3.2. Understanding the concept

Package source code or notebooks, a small example dataset, usage instructions and a short changelog. Protect private data.

3.3. Worked example

A clean project can be restarted and reproduced by someone who did not write it.

3.4. Try it in Python

print('Deliver: code, README, sample data, result summary')
See the algorithm step by step
  1. Run from clean state
  2. Review README and permissions
  3. Export the final artefact
