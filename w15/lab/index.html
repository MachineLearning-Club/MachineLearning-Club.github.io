Week 15 · Lab

FiiCode IV: Reproduce, Present and Hand Off

Teacher Guide One 60-minute session; core + optional Research

Learning outcome

Run a single final test with frozen settings; demonstrate and communicate reproducibility.

Teaching sequence

0–13 freeze configuration; 13–25 reveal hold-out results; 25–45 demonstrate application and tests; 45–55 peer review; 55–60 hand-off.

Core: reproducible observations, one experiment and an explanation in ordinary language. Research (3p): additional mathematics, model investigation or application engineering. All features and labels in this project are synthetic; do not infer student traits or real room conditions.

Contents
  • 1. Lock the configuration before reading final results
  • 2. Repeat the same result from an independent program
  • 3. Show the application to another person
  • 4. Hand off executable evidence
  • Submission

Independent preparation project: these are deliberately simulated examples for practising data analysis and software engineering. They are not official FiiCode rules, datasets, judging criteria or submissions.

1. Lock the configuration before reading final results

Run the notebook. First choose k on validation with the stated rule: maximize correct predictions, then use the smaller k when tied. This selects k=1. Document the weights and data split, and do not change them when you run the final evaluation.

The notebook contains the public educational test split; the test is intentionally absent from the Week 12–14 notebooks.

2. Repeat the same result from an independent program

Unzip the project and run python evaluate.py inside its folder. It needs no machine-learning package and prints validation comparisons, chosen k, final score and a confusion matrix. You should reproduce 38/45 correct on the synthetic hold-out.

Then run python evaluate.py --predict 35 40 4 1 60 to inspect a specific example. The five numbers correspond to occupancy, noise, Wi-Fi, outlets and duration, in that order.

3. Show the application to another person

Ask a classmate to supply a valid artificial room profile. Predict the class in the interface below, inspect its closest neighbours, then explain why the result might be inappropriate for a real person.

Review the practical project using the 20-point hand-off checklist. Record a failing test or limitation alongside the successful demonstration.

4. Hand off executable evidence

Prepare the project ZIP, a short README, the executed Week 15 notebook, a screenshot of the working UI, the final 38/45 confusion matrix and a one-paragraph limitation. Include a meaningful GitHub commit if your team used the repository workflow.

Deliverable: reproducible application and a short demo; not a fabricated competition submission. The teacher's collection link, if configured, is separate from local ZIP preparation.

Research (3p): define an ethical follow-up evaluation with genuinely collected and consented room feedback, including how you would keep the data independent of training.
