Week 15 · Advanced

FiiCode IV: Reproduce, Present and Hand Off

Teacher Guide One 60-minute session; core + optional Research

Learning outcome

Run a single final test with frozen settings; demonstrate and communicate reproducibility.

Teaching sequence

0–13 freeze configuration; 13–25 reveal hold-out results; 25–45 demonstrate application and tests; 45–55 peer review; 55–60 hand-off.

Core: reproducible observations, one experiment and an explanation in ordinary language. Research (3p): additional mathematics, model investigation or application engineering. All features and labels in this project are synthetic; do not infer student traits or real room conditions.

Independent preparation project: these are deliberately simulated examples for practising data analysis and software engineering. They are not official FiiCode rules, datasets, judging criteria or submissions.

Optional mathematical investigations. Read the Course before beginning; these proofs and derivations are not required to complete the 60-minute core lesson. Use your browser’s print command for a printable version.

Contents
  • Derivation A — what 38/45 actually measures
  • Reasoning B — compare validation and final test honestly
  • Investigation C — soundness of the testing claim

Derivation A — what 38/45 actually measures

The final observed accuracy is p̂ = 38/45 ≈ 0.8444. Because just 45 simulated examples are evaluated, one additional error changes the score by 1/45 ≈ 2.22 percentage points. The denominator matters as much as the percentage.

Exercise: recompute accuracy if two additional samples were misclassified. Explain why an observed percentage is not an exact guarantee about future classrooms.

Reasoning B — compare validation and final test honestly

Validation: 41/45 ≈ 91.1% for the selected k=1. Final test: 38/45 ≈ 84.4%. The difference is 3/45 ≈ 6.67 percentage points. These finite samples are different, and validation was also used to select k.

Exercise: distinguish three explanations for a difference: sample variation, model selection bias and distribution shift. Which can you actually establish using only these two small classroom subsets?

Investigation C — soundness of the testing claim

Suppose all Python tests pass and the browser displays the same predictions. What follows? The implementation may be consistent with its written specification and the provided fixtures. It does not follow that the synthetic label convention is fair, that the physical input sensors are reliable, or that the programme works for all real users.

Exercise: write a precise claim and a counterexample for each of three levels: code correctness, benchmark performance and usefulness in a real setting. Identify the additional evidence required for the last level.

References and reproducibility

All numeric claims can be reproduced with the same Python evaluation script and data. For Python input, output and basic mathematical notation, consult the club Python guide.
