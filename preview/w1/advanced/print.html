What can examples actually prove?

Progressive reasoning about generalisation, alternative rules and missing observations.

Preliminaries and notation

Let an input be a pair of Boolean features x, y (each is either 0 or 1). A classifier returns a Boolean label 0 or 1. A training sample is a finite collection of labelled inputs. A classifier is consistent with a sample if it gives the supplied label on every observed input.

We make no assumptions about the classifier's behaviour on inputs missing from the sample. Ordinary truth tables and pseudocode are sufficient to solve every problem.

Worked Example A — Two perfect models

Consider the observed examples (0,0) → 0 and (1,1) → 1. Two proposed classifiers are

def model_a(x, y): return x
def model_b(x, y): return y

Both are correct on every available training example. Evaluate both on the entire finite input space:

0000yes
0101no

1111yes

Solution and conclusion. Both models have 100% training accuracy. However, they disagree on two unseen inputs. Therefore perfect agreement with the training data does not logically determine the true classifier outside the observed sample.

Problem 1 — How many models are possible?

A binary classifier is allowed to choose independently between labels 0 and 1 on each of the four possible inputs. The labels of (0,0) and (1,1) are fixed by the training sample above.

  1. How many different classifiers remain consistent with the two observations?
  2. Explain your count without enumerating all 16 possible classifiers.
  3. What happens if one of the two unobserved cases is also labelled?

Selected solution. Two inputs remain unobserved. Each may independently receive 0 or 1; hence there are 2 × 2 = 4 consistent classifiers. One additional correctly labelled distinct input leaves one unobserved case and thus 2 consistent classifiers. This counting argument assumes there are no other restrictions on the class of possible models.

Problem 2 — The smallest distinguishing example

Assume the only possible true classifiers are model_a and model_b from Worked Example A.

  1. Choose one unobserved input that distinguishes the two hypotheses.
  2. Explain how learning its correct label lets you reject one of the two hypotheses.
  3. Why would a single such example not establish correctness if many other hypotheses were possible?

Hint: Look for a row in the truth table with unequal predictions.

Problem 3 — An irrelevant feature

Add another Boolean input z, but suppose the real output is still determined solely by x and y.

  1. Give two records with different z values and identical x and y. What can you conclude about their labels?
  2. A decision tree unnecessarily asks about z. Explain how a tree computing a function independent of z can be simplified to avoid tests of z.
  3. Why might training data that are incomplete make a learner incorrectly conclude that z is important?

Hint: For a truly irrelevant feature, changing only that feature cannot change the correct output.

Problem 4 — Generalisation requires an assumption

Suppose a learner has seen every input except one, denoted u, and must now predict its label.

  1. Construct two target functions that give exactly the same labels on all observed inputs but opposite labels at u.
  2. Use this construction to explain why no deterministic learner can be guaranteed to predict the label of every unseen u correctly without assumptions about the target function.
  3. Give a practical example of an additional assumption that could make learning useful.

Hint: Start from any proposed target function and flip its value only at u.

Observations for further study

A model is neither automatically wrong nor automatically reliable because some inputs were omitted. Generalisation becomes possible when we make useful assumptions: similar inputs often have related labels, the training data are representative, and the feature representation captures information relevant to the target. These are assumptions to investigate, not logical consequences of perfect training accuracy.

For additional practice: Experience AI — Bias in, bias out. Optional computational assistance: enumerate the four inputs in Python and compare the two models.
