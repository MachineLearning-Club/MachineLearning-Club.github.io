1. From one long script to several components

Real-life question. A monitoring program now contains sensor code, decisions and screen output.

Break a program into parts with clear responsibilities. Object-oriented programming is one way to organise related data and behaviour.

Worked example.

A Sensor supplies a measurement; a Controller decides an action; a Dashboard displays it.

class Sensor:
    def read(self): return 18
print(Sensor().read())

2. Objects and methods

Real-life question. The same app reads from several temperature sensors.

A class describes a type of object; an instance stores its own state and exposes methods. Keep examples small and practical.

Worked example.

Two Sensor objects can each have a different current value.

class Sensor:
    def __init__(self,value):self.value=value
    def read(self):return self.value
print(Sensor(17).read(), Sensor(21).read())

  2. Instantiate two objects
  3. Call a method

3. The ML pipeline

Real-life question. A classifier receives poorly formatted measurements.

An AI application has stages: collect → clean → predict → decide → display → test. Each stage should be testable independently.

Worked example.

Bad data should be rejected before a classifier makes an unreliable prediction.

def clean(value):
    if value is None: raise ValueError('Missing temperature')
    return float(value)
print(clean(18))
Show the process step by step
  1. Check the input
  2. Run the model
  3. Record the output and any warning

4. Saving and collaborating

Real-life question. Two students edit the same application at different times.

Versions track changes; Git commits store meaningful snapshots, while branches and pull requests support review. GitHub is optional for students without accounts.

Worked example.

'Add missing-data warning' is more informative than 'update'.

print('Commit message: Handle missing sensor readings')
