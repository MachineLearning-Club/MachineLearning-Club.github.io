Teacher Guide Course overview and teaching sequence

Course summary

Objects, project structure, testing and simple AI pipelines. This lesson uses a practical classroom situation: A smart classroom combines temperature sensors, a trained classifier and an information display.

By the end: learners should be able to describe each topic using an input, an algorithmic step and an observable result, then run a small Python example and identify one limitation.

1. From one long script to several components

1.1. Real-life situation

A monitoring program now contains sensor code, decisions and screen output.

1.2. Understanding the concept

Break a program into parts with clear responsibilities. Object-oriented programming is one way to organise related data and behaviour.

1.3. Worked example

A Sensor supplies a measurement; a Controller decides an action; a Dashboard displays it.

1.4. Try it in Python

class Sensor:
    def read(self): return 18
print(Sensor().read())
See the algorithm step by step
  1. Name three responsibilities
  2. Define inputs/outputs
  3. Connect the parts

2. Objects and methods

2.1. Real-life situation

The same app reads from several temperature sensors.

2.2. Understanding the concept

A class describes a type of object; an instance stores its own state and exposes methods. Keep examples small and practical.

2.3. Worked example

Two Sensor objects can each have a different current value.

2.4. Try it in Python

class Sensor:
    def __init__(self,value):self.value=value
    def read(self):return self.value
print(Sensor(17).read(), Sensor(21).read())
See the algorithm step by step
  1. Create a class
  2. Instantiate two objects
  3. Call a method

3. The ML pipeline

3.1. Real-life situation

A classifier receives poorly formatted measurements.

3.2. Understanding the concept

An AI application has stages: collect → clean → predict → decide → display → test. Each stage should be testable independently.

3.3. Worked example

Bad data should be rejected before a classifier makes an unreliable prediction.

3.4. Try it in Python

def clean(value):
    if value is None: raise ValueError('Missing temperature')
    return float(value)
print(clean(18))
See the algorithm step by step
  1. Check the input
  2. Run the model
  3. Record the output and any warning

4. Saving and collaborating

4.1. Real-life situation

Two students edit the same application at different times.

4.2. Understanding the concept

Versions track changes; Git commits store meaningful snapshots, while branches and pull requests support review. GitHub is optional for students without accounts.

4.3. Worked example

'Add missing-data warning' is more informative than 'update'.

4.4. Try it in Python

print('Commit message: Handle missing sensor readings')
