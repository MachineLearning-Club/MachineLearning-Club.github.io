11.1. A small useful program begins with a clear problem

Core idea

Describe who needs the program, what it should do and how you will know it works.

A classroom monitor reads a fictional temperature and shows a message. We begin with a simple requirement:

As a classroom caretaker, I want a warning when the reading is missing, so I do not mistake missing data for a comfortable room.

ExampleExpected result
Temperature 17 °CHEAT ON
Temperature 21 °CHEAT OFF
Reading missingCHECK SENSOR

The requirement is testable because all three expectations are stated before code is written. This simple idea comes from the requirements and testing portions of UAIC Software Engineering SE02.

11.3. Why a class can be useful

A class describes how related data and behaviour belong together. An object is one particular instance of that class.

Two sensors, one definition

class Sensor:
    def __init__(self, temperature):
        self.temperature = temperature

    def read(self):
        return self.temperature

room_a = Sensor(17)
room_b = Sensor(21)

print(room_a.read())  # 17
print(room_b.read())  # 21

Sensor is the class; room_a and room_b are objects. Both have a read() method, but they store different data.

Do all school programs need classes?

No. A two-line calculation is often clearer as a simple function. Use a class when the program benefits from keeping a piece of state and its related operations together. This lesson does not introduce inheritance or design-pattern catalogues.

11.4. Testing means checking a predicted result, not merely running code

Core idea

A useful test names an input and an expected result before comparing the result returned by the program.

def decide(temperature):
    if temperature is None:
        return "CHECK SENSOR"
    return "HEAT ON" if temperature < 19 else "HEAT OFF"

assert decide(17) == "HEAT ON"
assert decide(21) == "HEAT OFF"
assert decide(None) == "CHECK SENSOR"

Why the missing-reading test matters

Imagine the program accidentally treats None as zero degrees. It might switch the heater on as if a real measurement existed. The appropriate output is CHECK SENSOR, so a test exposes that mistake before the program is used.

What is a unit test?

A small test of one part of the program, often a function. For this lesson, three assert statements are enough. The UAIC SE06 and SE11 materials treat testing in far greater detail; frameworks such as JUnit are outside the school-level core.

11.5. Change one thing, test again, save a meaningful version

Edit

Describe one small desired change, such as adding a missing-data warning.

Test

Run the original and the new test cases. Reject a change that breaks them.

Save

Record the version: Add missing sensor warning.

An AI assistant can suggest changes, but a suggestion is not proof that the code works. Review the diff and run tests yourself. The supplied university document Behind the Scenes includes a real example of a teacher correcting an AI coding agent's mistaken working directory while it was carrying out a task.

Practise a version history without registration in the Git, GitHub & AI Editing guide. A real GitHub account is optional.
