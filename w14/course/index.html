Week 14 · Course

FIICode III: Improving and Testing

Teacher Guide Course overview and teaching sequence

Course summary

Improve one thing at a time, using actual measurements. This lesson uses a practical classroom situation: A prototype works for most test inputs but fails on some important cases.

By the end: learners should be able to describe each topic using an input, an algorithmic step and an observable result, then run a small Python example and identify one limitation.

1. Measure the current weakness

1.1. Real-life situation

An app gets seven of ten categories right.

1.2. Understanding the concept

An average score does not identify which errors matter; inspect mistakes by input type and class.

1.3. Worked example

If all three failures occur on night-time readings, investigate that feature before changing the entire model.

1.4. Try it in Python

actual=['A','A','B','B']; pred=['A','B','B','B']
print(sum(a==b for a,b in zip(actual,pred)))
See the algorithm step by step
  1. Find failed examples
  2. Group by cause
  3. State a hypothesis

Try this: change one input or value in the code, then predict the new output before running.

2. Controlled experiments

2.1. Real-life situation

Two students independently change parameters and features.

2.2. Understanding the concept

Change one factor at a time and compare results on the same validation data. Avoid choosing a model based on final hidden test answers.

2.3. Worked example

Baseline: 0.70; one feature added: 0.75; check whether improvement repeats.

2.4. Try it in Python

before,after=.70,.75
print(round(after-before,2))
See the algorithm step by step
  1. Record baseline
  2. Make one change
  3. Compare on identical data

Try this: change one input or value in the code, then predict the new output before running.

3. Make the demo reliable

3.1. Real-life situation

The project works only on the author's computer.

3.2. Understanding the concept

Keep a reproducible environment, sample inputs and clear steps. Handle missing data and explain limitations.

3.3. Worked example

A README should let another student run the same notebook and understand the outputs.

3.4. Try it in Python

print('README: inputs, how to run, known limitations')
See the algorithm step by step
  1. Restart from clean state
  2. Run a sample case
  3. Record expected output
