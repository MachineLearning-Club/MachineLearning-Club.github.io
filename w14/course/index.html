Week 14 · Course

FiiCode III: Improve, Measure and Test

Teacher Guide One 60-minute session; core + optional Research

Learning outcome

Compare candidates fairly on validation data; read a confusion matrix; report one error.

Teaching sequence

0–10 recall baseline; 10–25 compare k values; 25–42 error-analysis experiment; 42–53 controlled ablation; 53–60 freeze a setting.

Core: reproducible observations, one experiment and an explanation in ordinary language. Research (3p): additional mathematics, model investigation or application engineering. All features and labels in this project are synthetic; do not infer student traits or real room conditions.

14.1. Decide what counts as an improvement

Week 13 made a real prediction. Week 14 asks whether it works reliably on examples the classifier did not use as neighbours. We compare k=1, 3, 5 and 7 using exactly the same 45 validation examples, the same features and the same distance formula.

The chosen model uses k=1, the smaller value among the two tied best validation scores. This rule must be established and recorded before looking at the final test. Even the best validation accuracy is influenced by our choice from several candidates and should not be presented as an untouched final result.

14.2. Inspect more than one headline percentage

A confusion matrix shows which predictions are wrong, not just how many. Rows are true classes, and columns are predictions. The k=1 model produces the following table on validation:

Avoid1320

The diagonal totals 13+15+13=41. The four mistakes involve the consider class; there are no direct avoid-versus-good errors in these 45 examples. This observation is only about the small simulated validation set.

Worked recall calculation

Recall for the actual good class is 13/15 ≈ 86.7%: of 15 truly good simulated rooms, two were called consider. A different question—precision—would examine how many predicted-good rooms were actually good.

14.3. Change one variable and inspect errors

Select k and press Evaluate on validation set. The matrix is recomputed, not merely recoloured. Look for an example with the wrong prediction and compare its closest neighbours.

Loading the classroom experiment…

Controlled ablation: the Week 14 notebook removes the Wi-Fi weight while keeping the same examples and k=1. The validation score falls from 41/45 to 39/45. This supports only the observation that Wi-Fi helped this specific experiment; it does not establish causality or guarantee the feature will help elsewhere.

14.4. How to lose fairness without noticing

Suppose you try 100 combinations, keep the highest validation score and only report that best value. The selected score may be optimistic for fresh data. It is worse to change a model based on the final test: then the test is no longer independent of model selection. Record every model tried and reserve one final evaluation.

Also check that the same labelled example does not appear in both train and validation. An algorithm that memorises training records might look better than it really is if duplicates leak into evaluation.

Research: why a bigger score can still be misleading

Consider two datasets, one with only obvious cases and one with difficult, ambiguous cases. The same algorithm might score differently without any change in its implementation. A fair before/after experiment fixes the data and scoring procedure.

14.5. Freeze one decision

Your deliverable is a comparison table, one confusion matrix, one documented mistake, one ablation result, and a short note specifying k=1 for the upcoming final demonstration. Do not examine the final test to improve this choice.

Exit ticket: Explain why k=1 and k=7 tie for the best validation score yet do not necessarily make the same individual predictions.
